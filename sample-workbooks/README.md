# Sample workbooks — bring your own

**This folder ships empty on purpose.** Drop `.twb` / `.twbx` / `.tds` / `.tdsx` files in here,
then point the converter at the folder:

```powershell
.\scripts\Convert-TableauToPowerBI.ps1 -Source .\sample-workbooks -Output .\out
```

## Why it's empty — please read before you re-add anything

This repo used to bundle four real Tableau Public dashboards so a fresh clone could convert
something realistic with zero setup. That was a mistake, and they have been removed.

A workbook being **publicly viewable on Tableau Public is not a licence to redistribute it.**
Those `.twbx` files are the authors' work — and a packaged `.twbx` carries the *data* as well as
the design. Committing them into an MIT-licensed repo re-publishes someone else's dashboard, and
their data, under a licence nobody granted. The same applies with much sharper teeth to anything
pulled from **Tableau Cloud/Server or a customer tenant**, where the file is very likely to
contain real business data.

`.gitignore` now blocks workbook binaries in this folder, so this can't recur by accident.

**Rule for this repo:** the only Tableau files committed here are ones generated by the engine's
own synthetic fixtures (`sample/`, `sample-hard/`, `sample-tablecalc/`) — those we authored.
Everything else is fetched by the person running the tool.

## Getting realistic workbooks to test with

**Option 1 — Tableau Public (a few clicks, no account needed to browse).**
Open [Tableau Public](https://public.tableau.com), find a dashboard you like — the *Viz of the
Day* gallery is the usual starting point — and use the **Download** button in the bottom-right
toolbar, choosing **Tableau Workbook** to get the `.twbx`. Not every author enables downloads;
pick one that does. Save it into this folder and run the command above.

For reference, the four workbooks this accelerator was originally benchmarked against are
identifiable on Tableau Public by these workbook IDs (searching the title works too):

| Workbook ID | Authored in | What it exercises |
|---|---|---|
| `SampleSuperstore-SalesPerformance` | Tableau 2022.1 | Classic Superstore KPIs + calculations |
| `SuperstoreSalesDashboard_17403964185480` | Tableau 2024.3 | Compact sales dashboard, multiple sheets |
| `GolfSuperstorePerformanceOverview` | Tableau 2023.3 | Different schema + calculation mix |
| `SuperstoreSalesandOrdersDashboard-TheBarChartWay` | Tableau 2025.2 | Large, multi-datasource (federated) workbook |

They are listed so the published numbers stay reproducible, not as a recommendation to
redistribute them. Download them yourself; don't commit them back.

**Option 2 — generate a synthetic estate, zero downloads.** The engine's own fixtures can
materialize a small multi-source estate (relational + workbook, a 3-way cross-database federated
datasource, and embedded flat-file datasources):

```powershell
$fix = "$PWD\engine\skills\tableau-migration\tests\integration"
py -3.11 -c "import sys; sys.path.insert(0, r'$fix'); import fixtures; fixtures.materialize_all(r'$PWD\sample-workbooks')"
```

Honest caveat: this exercises **source-type breadth**, not dashboard complexity. These fixtures
are small — three worksheets and a dashboard. They will not reproduce the visual-fidelity numbers
in the top-level README, which came from a 13-workbook estate of real dashboards. Use them to
prove the pipeline runs end to end across source types; use Option 1 to judge fidelity.

**Option 3 — your own or your customer's files.** Use the `workbooks/` folder instead. It is
git-ignored for exactly this reason, so nothing sensitive is ever committed.

## Which folder do I use?

- **`sample/`** — the single tiny synthetic file used by the 60-second Quick start. Ships with the repo.
- **`sample-workbooks/`** (this folder) — realistic workbooks *you* supply, using either option above.
- **`workbooks/`** — **your own / customer files.** Git-ignored.

Each run produces, per workbook, a typed **TMDL** model, calc→**DAX** (originals kept as
annotations), an openable **`.pbip`**, plus `report.json` + `summary.md`. Some calculations are
intentionally flagged for human review — that's the correct-or-abstain design, not a failure.
